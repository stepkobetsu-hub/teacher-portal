# 講師初期登録・登録情報の変更

公開入口：講師ポータルの「講師初期登録」 → `registration.html`。

## 利用手順

1. 新しい講師は「はじめての登録」で姓名・フリガナ・生年月日・メールアドレスを入力して送信する。登録コードは不要。
2. 画面に講師番号が表示される。初期パスワードは生年月日の月日4桁。教室は確認メールを受け取り、講師マスターD列に1を入力して在籍者にする。
3. 住所・給与振込口座・マイナンバーは「登録情報を変更」→「登録情報の追加・変更」で後から入力する。マイナンバーは登録済みかどうかだけ表示し、番号を再表示しない。
4. 既存講師のパスワード設定・再設定は従来の専用リンクで利用できる。教室で本人確認を行う。
5. 共用端末では利用後ログアウトする。

## 確認メール

- 画面下部の「確認メール送信先の設定」から、スタッフ認証後に講師本人以外の送信先を1～3件設定する。
- 未設定時の初期値は `mintcocoajasmine@gmail.com`、`admin@educrest.jp`。設定はScript Propertiesへ保存し、画面やリポジトリへ認証情報を保存しない。
- 初期登録、既存講師のパスワード設定・再設定、登録情報変更、パスワード変更の完了時に、講師本人と設定済み送信先へ個別に確認メールを送る。初回登録メールにはD列へ1を入力する案内を含める。口座・マイナンバーなどの内容はメール本文へ記載しない。

## 保存先・列対応

指定の「給与明細2026-6-」／「講師マスター」（sheetId 2020620808）を使用。見出しは4行目、データは5行目以降。

| 列 | 登録内容 |
| --- | --- |
| A | 7000番台の最大値＋1。確認時の最大7092、次回7093。同時登録はスクリプトロックで直列化 |
| B / C | 別入力した姓・名／フリガナを半角空白で結合 |
| D | 初回登録時は空欄。管理者がメールの案内に従い1を入力 |
| E / F | 郵便番号（先頭0保持）／住所 |
| G | 初回登録時は空欄。本人の更新では変更しない |
| H / I / J / K | 銀行コード／支店コード／種別／口座番号。文字列で先頭0を保持 |
| L / M | 生年月日／L列からM3（TODAY）を基準に年齢と月数を算出 |
| N | 既存の扶養控除申告を維持。新規登録時は空欄 |
| O / P | マイナンバー（任意・12桁）／メールアドレス |
| Q | `STEP-講師番号` を自動入力。後から手動で上書き可能 |
| AJ | 生年月日の月日4桁を文字列で自動入力。後から手動で上書き可能 |

ゆうちょは利用者指定に従いH=9900、I=5桁の記号、J=空欄、K=最大8桁の番号。他行振込用の店番への自動変換は行わない。

## 実装・運用

- フロント：`registration.html`、`registration.css`、`registration.js`。GitHub Pages、ブラウザWeb Crypto。
- バックエンド正本：`gas/TeacherRegistration.gs`。本番Apps Script「BREVO_API_KEY」の既存「コード.gs」末尾へ同モジュールを結合し、doPostにteacherRegistration専用分岐を追加。その他のコード・AuthCompat.gs等を維持する。
- Apps Script ID：`1jZRwuaEqbhgg6xRQq63ke5QO9Wc2ulsGOA_gbmHfiehQIsr9NQLLqSZR`。
- 既存デプロイID：`AKfycbzYpm-16ahuZ3BRFKRT-iSvR9nThsYcTOhxplyBp4bZmVmehfTYZEEl18THzJasypOsTQ`。WebアプリURLと公開範囲は変更しない。
- 登録APIはPOSTのみ。本人セッションから行を決め、クライアントが指定した別講師番号では更新しない。保存前に編集元の版を照合し、他画面の更新を上書きしない。
- パスワードはブラウザでPBKDF2-SHA256（600,000回、ランダムsalt）処理し、サーバー側の秘密pepperでHMAC化してScript Propertiesに保存する。平文・派生認証値をシートやログへ保存しない。
- 1時間のセッションをハッシュ化してScript Propertiesに保持し、ログアウトとパスワード再設定で無効化。パスワード変更時は古いセッションを全て拒否。ブラウザはログイン情報・個人情報を永続保存しない。
- 初回登録はメールアドレスのハッシュで二重登録を防ぐ。既存講師のパスワード設定用コードは従来どおりハッシュのみ保存。処理中断時の採番予約と同一内容の再送を考慮する。
- 認証情報を復元できなくなるため、TR_V1_PEPPERとTR_V1_ACCOUNT_*を不用意に削除・変更しない。GitHubへScript Propertiesの値を掲載しない。
